# DCU-2026-07-26-08 — Direct Android updates keep one signing identity

## Decision

Direct-distribution production APKs for
`io.github.holyglory.devcoordinator` use one dedicated RSA-4096 signing key
with alias `devcoordinator-direct`. Its certificate subject is
`CN=PerssKos DevCoordinator Universal, OU=Direct Distribution, O=PerssKos`,
its SHA-256 fingerprint is
`0bbd3187d8e2ea0ee678c57108760cb4078816d90e250ff5dedbe9e632367232`,
and it is valid through 2053-12-11.

The keystore and its password stay in a private release-credential store
outside this repository with owner-only permissions. Release automation must
receive them through protected environment secrets, verify the expected
fingerprint after signing, and never attach debug-, ad-hoc-, self-signed-test-,
or unsigned artifacts to a stable production release.

## Why

Materially distinct options were:

- keep publishing Android debug APKs, which are installable for testing but
  use a runner-specific identity and therefore cannot guarantee upgrades;
- wait for every Play, Apple, and Windows publisher identity before making any
  Android package installable; or
- establish a durable direct-Android identity now while preserving separate
  store and desktop signing channels.

The dedicated direct key is the only option that gives copied APKs one stable
package identity today without pretending that it is an Apple Developer ID,
Windows trusted publisher certificate, or Play App Signing identity. Changing
this certificate later would break direct install-over compatibility, so the
keystore requires an offline owner-controlled backup before the distribution
channel is considered operationally complete.
