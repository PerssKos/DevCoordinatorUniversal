# DCU-2026-07-25-05 — The legacy bearer is process-session-only

The legacy loopback bearer is a sensitive host-wide preview credential. The
user did not require automatic reconnect, so current builds retain that bearer
only in process memory. Preferences persist only the non-secret host profile
that prefills the next connection form.

This replaces the earlier two-store transaction design. A non-secret
`credentialCleanupPending` marker handles an ordinary failure in either store,
but it cannot prove disconnect intent when the marker write, profile removal,
and secure-key deletion all fail. A second tombstone has the same limitation
when all durable writes fail. Refusing to close the live service until the
marker succeeds would make Disconnect visibly fail and still allow the old
records to reconnect after restart.

The fail-closed invariant is therefore structural:

1. `SecureTokenStore` reads and writes only the current process-session value;
2. it may delete the exact legacy secure-storage key, but never reads or writes
   a durable bearer;
3. every cold launch attempts deletion of that exact legacy key, even when no
   saved profile or pending-cleanup marker remains;
4. the explicit legacy-key purge is independent of the session read and does
   not discard a valid current-process bearer;
5. clearing drops the in-memory value before attempting the fallible legacy-key
   deletion;
6. a new process begins without a bearer, so a saved profile cannot connect
   until the user supplies the token again;
7. disconnect still closes the service first, records the cleanup gate,
   removes the profile and legacy key, and blocks new connections with an
   explicit retry if confirmed cleanup is incomplete.

Regression tests retain the old profile, old durable bearer, and false marker
under simultaneous simulated failures, construct a fresh session store, and
prove that initialization exposes no credential to the coordinator factory.
Adjacent tests cover settings-write failure, failed legacy-key deletion,
an orphaned key with no profile or marker, restart, explicit recovery,
transient initial marker failure, transient cold-launch purge recovery without
discarding the non-secret saved profile, and failed-connect rollback.

Future native-v2 rotating refresh credentials are a separate scoped credential
class and require a dedicated secure-store/session-revocation design; they must
not reuse this legacy bearer path.

Android additionally excludes all application storage domains from cloud,
device-transfer, and legacy backup rules so encrypted secure-storage metadata
cannot be restored without its device-bound key.
