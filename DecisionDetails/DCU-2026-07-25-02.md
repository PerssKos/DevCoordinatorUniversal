# DCU-2026-07-25-02 — Authority and remote access boundary

## Evidence

The existing coordinator HTTP contract binds only to IPv4 loopback and protects
`/v1/*` with one private host token. DevOpsConsole is the remote boundary, but
its `/api/*` contract is a browser BFF authenticated by an HttpOnly Google
session cookie and same-origin mutation checks. It does not expose native
access/refresh tokens, device sessions, revocation, scopes, idempotency keys,
or a versioned OpenAPI contract.

## Required server extension

The native gateway contract must provide:

- OAuth/OIDC authorization code with PKCE in the system browser;
- short-lived user-scoped access tokens, rotating refresh tokens, revocation,
  and device-session management;
- OpenAPI 3.1 DTOs, capabilities, minimum-client version, opaque identities,
  idempotency keys, operation IDs, and RFC 9457 errors;
- revision preconditions and server-advertised action blockers;
- cursor pagination for events/logs and exact lifecycle plan/apply semantics.

Until that gateway is deployed, only a macOS app on its verified coordinator
host can use the legacy API. Android, Windows, and off-host desktop setup must
show an honest capability blocker rather than request or store the host-wide
token. The source project documents a native macOS client and separately
requires a future Windows authority; it does not establish a safe Windows
loopback host implementation.

The local client first probes the canonical public `/healthz` marker with a
bounded, no-redirect request before it reads the host bearer. This prevents an
accidental wrong-port disclosure, but the marker is public and therefore does
not authenticate a peer that is already inside the host trust boundary. The
legacy path remains a local preview until an identity-bound transport closes
the listener-replacement race recorded in the completion ledger.

## Client foundation

The separate application repository implements the required core as a strict
HTTPS transport and typed DTO boundary. Public metadata is separated from
authenticated requests; remote inventory requires a strong ETag and rejects
partial truth; mutations require exact targets, revision preconditions, and
UUID idempotency keys; and inconclusive transport outcomes remain unknown
until authoritative reconciliation. This foundation does not replace the
missing provider, user/device authorization flow, or application adapter.
