# DCU-2026-07-26-09 — Stable Android releases are signed off GitHub

## Decision

The direct Android private key and password files remain on an
owner-controlled release host and are never copied into the repository,
GitHub Environment, Actions, artifacts, logs, or Releases. The canonical local
publisher requires a clean `origin/main` commit and its exact pushed SemVer
tag, invokes the clean-archive builder, stages the signed APK and checksum in a
draft, downloads them to a new directory, revalidates checksum/signatures/
certificate/package/version/zip alignment/merged callback/gateway/update
source, and only then publishes the stable Release.

GitHub Actions has read-only contents permission. On release publication it
checks the tag and main ancestry, reruns source/contract tests, downloads the
two public assets, repeats artifact validation against the pinned public
certificate fingerprint, and verifies anonymous latest-release discovery.
Failure does not grant GitHub access to the private signing identity.

## Why

Material alternatives considered:

- GitHub Environment secrets would provide unattended builds, but a
  long-lived direct-update key would then be usable inside a third-party cloud
  runner and repository-administration boundary. The attempted configuration
  was stopped before any secret was uploaded.
- A one-off `gh release create` command would keep the key local, but would not
  guarantee a clean source commit, correct tag, draft-before-live ordering,
  clean-download validation, or safe reruns.
- Publishing an unsigned APK and asking users to trust a checksum would not
  preserve Android install-over identity and would not authenticate future
  updates.
- Play App Signing remains appropriate for a future Play channel, but it is a
  separate distribution identity and cannot retroactively replace the direct
  sideload certificate.

The selected split confines the private operation to the owner's release host
while making every public property independently reproducible and observable.

## Evidence and verification

`tool/build_android_release.sh` and `tool/publish_android_release.sh` fail
closed on dirty source, tag/remote mismatch, invalid private-file placement or
permissions, lint failure, signer drift, manifest drift, checksum drift, or
download mismatch. `.github/workflows/android-release.yml` contains no signing
secret and performs read-only post-publication validation. Release acceptance
requires a successful local publish, successful public workflow, anonymous API
discovery, and an update prompt from a previously installed lower SemVer.
